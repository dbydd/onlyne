# OMP 接入的交互设计

本文记录 `omp-onlyne` 的界面组织、呈现规则和交互选择。模型可见的参数、结果事实与恢复要求由 RFC 0008 与《OMP 接入契约》规定；本文说明这些要求如何在 OMP 里落成界面。协议与契约没有规定的地方（分页、颜色、卡片结构、文案），以本文为准。

## 1. 两个观察者

| 观察者 | 看到什么 | 数据来源 |
|---|---|---|
| 模型 | `msg` 工具、来信片段、todo | 库的 thread/inbox 记录与注入游标 |
| 人 | `/onlyne` 覆盖界面、状态行、bootstrap/config 表单 | 运行时快照与 `onlyne://` 视图的同一份数据 |

两边读同一份事实。界面不维护第二套状态，也不在快照里放只有界面能算的结论。用户可见的信息（密钥材料除外）都有对应的 `onlyne://` 路径，agent 可以直接读；这是界面与内部路径共享数据的要求，不是额外实现。

## 2. 入口

| 命令 | 行为 |
|---|---|
| `/onlyne`、`/onlyne menu` | 打开覆盖界面，默认停在「队列」页 |
| `/onlyne init` | 仅在未配置时打开首次表单；已配置时提示改用 `config` |
| `/onlyne config` | 打开同一张表单，预填已保存的值 |

命令带子命令补全与一行说明。没有交互式终端时，命令不打开面板，改为一条可见消息说明如何初始化。会话切换、分支切换、会话关闭都会取消正在打开的面板，避免面板引用已失效的会话。

## 3. 状态行

状态行位于编辑器上方，固定一行，不随内容增减：

```text
<node 短名> · <region 短名>   nodes N   neighbors N   alert N   unread N
```

- 模块横向铺满可用宽度，间距就是分隔，不画竖线，也不左对齐挤在一边。
- `nodes` 是连通拓扑内的可达节点数，`neighbors` 是单步可达邻居数（有密钥时只算已交换的），`alert` 是未确认且未注入的来信，`unread` 是未注入的来信。历史累计值不显示。
- 发现失败时追加一个 `discovery` 模块显示原因；没有运行时显示 `unconfigured` 或 `starting`。
- 刷新由 2 秒轮询加运行时通知触发；渲染出的整行与上次相同就不重绘。

## 4. 主界面

- 外层高度由终端行列算出，内容只在内部滚动或分页。任何页面的外层尺寸都不由消息条数决定。
- 顶部只有一个标题；标题下方是状态摘要与操作区，允许换行。
- 四个页签占满一行：队列、对话、发现、联系人。页签是独立组件，不挤在标题右侧。
- 内容用卡片：标题在卡片顶部，描述在卡片内部，可以多行。不把多段信息压成一行。
- 选中效果是给整块背景加一层淡蓝，不是按钮配色，也不是彩虹描边。按钮自己用按钮色。

## 5. 页面

### 5.1 队列

四个分区：来信、出站、本地上下文、判定。每个分区先显示总数，再列出条目；条目是卡片，标题行带时间。超过预算时显示「还有 N 条」，不压缩行高。判定分区目前还没有快照来源，界面显示为空；判定记录的实际读取入口是库的 `decision/` 记录。

队列读的是运行时快照：未注入的 inbox 行、`running`/`unbound` 的执行上下文、`pending`/`unknown` 的出站记录。已注入的来信不出现在队列里；outbound 只列未结案的两态。

### 5.2 对话

三列：左侧 thread 列表，中间消息流与输入框，右侧成员与成员详情。

- thread 列表一行一项，显示标题、消息条数、未读数。选中后中间显示该 thread 的消息流；超出可视行数的旧消息只标注剩余数量，需要全文时读 `onlyne://threads/<id>`。thread 不折叠，收起会让人丢失「这个对话到哪了」。
- 消息卡片显示序号、方向、作者、时间与正文。列表行只显示首行与「+N 行」；点击卡片打开从底部弹出的详情，详情内可上下滚动，正文完整换行。省略只发生在列表，不发生在详情。
- 输入框是原生编辑器，`Enter` 换行；发送是「发送」按钮。发送目标默认是 thread 对端，选择其他收件人走详情里的「用作发送目标」，界面上明确显示「发送到谁」。这条路径与 `msg` 工具共用库的发送与消费记录。
- 成员列表显示每个成员的交换阶段；成员详情是一张卡片：指纹、域、状态、端点、最后可见时间，操作按钮在卡片底部。

### 5.3 发现

按域分组列出可达候选。每组标题是域短名与节点数；没有域的候选单独成组。

- 每个候选是卡片，显示节点短名、端点、最后可见时间与信任阶段，操作按钮只有与该阶段相符的项：请求交换密钥、同意交换、撤销信任、用作发送目标。
- 交换申请**不从这一页自动发出**。用户勾选或点击某位候选，才会进入指纹核对；同域不构成自动连接或自动信任的依据。
- 卡片边框表达认证状态：无框是无认证，蓝框是交换进行中（本侧已发或对端已发、尚未双方批准），绿框是已完成交换。被选中的卡片在边框之外再加淡蓝背景，不改变边框语义。
- 顶部有「刷新发现」，失败原因显示在页内，不弹窗。
- 未选中任何候选时，页面说明下一步：确认对方已启动、在同一网络，或到 bootstrap 填一个初始地址。

### 5.4 联系人

两张列表，从上到下：

1. **待你确认**：对端已发来交换申请、等待本节点批准的节点。这是审核入口，不再是发现页的附属品。
2. **已建立**：双方完成交换的节点。每项可查看指纹、用作发送目标、撤销信任。

请求交换是发现页的动作；联系人页只做批准与撤销。这样「谁能和我通信」与「网络里还有谁」分开。

### 5.5 密钥交换卡片

打开核对时，从底部弹出一张卡片：对方节点短名、对方声明的域、指纹（分组显示）、本节点将出示的公钥指纹，以及两个按钮「确认并发送申请」「取消」。确认按钮是唯一提交路径；卡片关闭不产生任何记录。指纹在展示与提交之间若发生变化，提交失败并提示重新核对。

### 5.6 首次表单与配置

字段固定为六项：

| 字段 | 说明 |
|---|---|
| Region | 必填。有 Tern 时用当前 session 名作为建议值，用户确认后保存为 `urn:onlyne:region:<短名>` |
| Node id | 必填，初始为空，由用户填写稳定身份；短名保存为 `urn:onlyne:agent:<短名>` |
| Server bind | 默认 `127.0.0.1` |
| Node key | `project` / `global` / `none`。提示中写明路径与 git ignore 要求 |
| Page size | 1～100，默认 50 |
| Initial node address | 可选。自动发现不可达时联系一个已有节点；不写入配置 |

「保存并启动」写配置、启动运行时、立即联系初始地址；任一步失败都显示停在哪一步。「取消」不写配置、不启动节点。表单不收集 endpoint、port、peers、判定模型或补充窗口，这些由运行时生成或由判定决定。

## 6. 模型侧的呈现

模型不经过面板，但呈现规则与面板同源：

- 来信注入使用自定义消息类型 `onlyne.inbound`，投递去向用 `onlyne.routing`，补充到子代理用 `onlyne.supplement`；`attribution` 是 `agent`，不冒充用户发言。排队条目用 `appendEntry`，不进上下文。
- 消息列表的索引属于信封：`[seq] 方向 · 作者 · 时间 · @提及`，正文逐行加两个空格和 `> ` 前缀。多行正文不产生新条目，渲染前缀不写回正文。
- 列表行只显示首行和 `[+N 行]`，全文通过读取该消息取得。
- 待办的 explanation 首段固定为 `Source: <thread>/<seq> from <author>`，其余内容由模型编辑；来源关联的权威记录在本地存储，不在标题。
- 工具结果是「可读文本 + 结构化 facts」两段。事实部分只写实际发生的接纳、等待、关系与计划，不把「已发送」写成「已答复」。

## 7. Tern 与纯终端

界面按 OMP 的组件协议描述（`describe`），由宿主决定渲染：纯终端走 ANSI，Tern 走富文本组件。同一次描述必须给出同样的信息，不允许一条信息只在其中一种渲染里出现。Tern 只影响 bootstrap 的 region 建议；没有 Tern 时表单照常可用，不用 cwd 或前缀猜 session 名。

例外是输入框：它由编辑器组件自己处理按键。除此之外的连接、批准、撤销、翻页、发送都是点击，不设组合键。当前实现仍保留 `Escape` 关闭面板与 `Ctrl+Enter` 发送，这两项是编辑器习惯，不是操作入口。

## 8. 与设计不一致的现状

发现页说明文字现在写明域只决定归组与发现范围、每个节点对都要显式交换密钥；刷新发现不再自动发起交换，见 [README.md](README.md) 第 7 节。

同样待落地的还有候选卡片的边框状态：当前实现用阶段文案与操作按钮表达认证状态，只给选中项换底色，蓝框/绿框尚未实现。

消息详情也还没有实现：当前消息卡片把正文压到 3 行，点击只把作者设为发送目标，没有详情面板。按本设计，点击应打开完整正文，发送目标选择另设入口。
