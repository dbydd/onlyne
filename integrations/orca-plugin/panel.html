Onlyne Sessions

只读 supervisor 看板 · pluginApi v1（EXPERIMENTAL）

这块面板是静态沙箱文档。Orca 只允许面板调用三个 host 方法 （workspace.readContext / terminal.sendText / notifications.show），面板不能读插件 worker 的状态、不能调用插件命令、 不能 fetch 任何本地文件。

所以实时看板不在面板里，而在桌面通知与 设置 → Plugins → 该插件的日志里：看板结构变化时插件会推一条通知。

工作区—

看板怎么看

tab 轴一次 orca terminal list --json：所有 worktree 的所有 tab，平铺 session 轴每个配置的 server root 一次 onlyne --server-root <S> sessions --json（外加 roles）
●活 tab：该 tab 的 connected=true ○没连上的 tab，或 session 轴有、tab 轴没列出的行

join 只看标题：tab 标题（去掉首尾空白）正好等于 onlyne:<task_id> 时，才标注到那一个 task 行；对不上任何 session 的 tab 落在「未 join 的 tab」一节。这个链接是弱的——面板里的进程可以用 OSC 改标题把它抢走；权威身份在 adapter/pi 插件协议里，看板只是 supervisor 的方便视图。

行内四段：task · lifecycle/agent · lastOutputAt 相对时间 · pane_key 短形（tab8:leaf8）。顶部一行是 summary： N roots · N roles · N tabs (M live) · N sessions (K working)。 没配 serverRoots 也成立：看板就只剩 tab 轴。

命令

面板不能直接触发插件命令；点按钮会把该跑的命令名发成一条通知，去命令面板执行即可。

跳转认两种前缀：task id，或 <tabId>:<leafId> 面板短形（tab8:leaf8 也接受）。命令面板传不了参数，所以「跳转 tab」在没有参数时只在 恰有一个活 tab的情况下生效，否则会通知候选清单。需要带前缀调用时用 plugins.invokeCommand： {"pluginKey":"onlyne.onlyne-sessions","commandId":"onlyne-sessions.focus","args":{"task":"task8"}}

跳转会切前台焦点（orca terminal switch），只在你自己触发时发生。

权限（consent）

  • workspace:read —— 读当前焦点工作区的名字/分支/tab 数（本面板的读取按钮）
  • notifications:show —— 推送看板与错误
  • events:subscribe —— worktree 创建/移除、agent 状态变化后 2s 防抖重扫

面板自己的调用失败时会显示错误码（例如 consent_required：去 Settings → Plugins 里补授权）。

已知边界

  • 生命周期只属于 onlyne backend：插件绝不建/关/改名 tab，也不写任何 onlyne 文件。
  • 会话状态只从配置的 server root 的 admin socket（<S>/.onlyne/run/s）读；某个 root 连不上只影响它自己那一节，其他 root 与 tab 轴照常渲染。
  • join 用的标题是弱信号，可能被 OSC 偷走；权威身份在 adapter/pi 插件协议里。
  • 5s 兜底重扫只在 worker 活着时跑；worker 被回收后，下一个事件或命令会重新拉起它。
  • pluginApi v1 仍是 EXPERIMENTAL：Orca 升级后请先跑一次「重新扫描」确认 JOIN 还成立。
