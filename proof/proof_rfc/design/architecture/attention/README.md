# 关注

本模块负责一条已接纳消息的主动关注义务，以及它在成员上下文中的消费状态。它不负责消息存盘与序号分配。

## 依据

主动关注由 `mentions` 和回复关系决定，消息本身仍然只存盘一次（来源：`docs/rfcs/0003-messages.md:33-64`）。运行时维护自己的注入游标，持久接收与上下文消费分别提供证据（来源：`docs/rfcs/0004-events-and-views.md:151-158`）。关闭 thread 后，未消费的关注仍须交付（来源：`docs/rfcs/0008-omp-surface.md:282`）。

## 为什么

本模块在数学关系中连接 owner 的义务、成员的持久接收和运行时消费。这三类事实各有权威，模型不将它们视为一个共享存储。

## 语义

``Attention`Inject`` 的调用依赖宿主确认上下文消费。void API 返回只证明提交尝试，消费结果未知时不能推进记录。跨 await 工具结果与自动片段的协调尚缺 RFC 契约，附录单独搜索该重复展示窗口。

节点可以长时间离线，离线结束时用它自己的接收记录重新取回上下文，不依赖一次性的通知。
