# 关注

本模块负责一条已接纳消息的主动关注义务，以及它在成员上下文中的消费状态。它不负责消息存盘与序号分配。

## 依据

主动关注由 `mentions` 和回复关系决定，消息本身仍然只存盘一次（来源：`docs/rfcs/0003-messages.md:33-42`）。运行时维护自己的注入游标，`received` 不等于已注入（来源：`docs/rfcs/0004-events-and-views.md:134-140`）。关闭 thread 后该 thread 退出自动片段，历史仍可读（来源：`docs/rfcs/0008-omp-surface.md:154`）。

## 为什么

义务、接收与注入放在同一模块，因为它们共同回答「这条消息是否仍需要进入某个上下文」。把义务留给 owner、把注入留给成员，会让两侧各自判断消费是否完成。

## 语义

``Attention`AttentionState.due`` 在接纳时产生，在消费前不消失，无论 thread 是否已关闭。``Attention`Automatic`` 只反映当前自动路径，它排除已关闭 thread，因此不能用来判定义务是否仍然存在。

节点可以长时间离线，离线结束时用它自己的接收记录重新取回上下文，不依赖一次性的通知。
