# Onlyne v3 RFC 故障发现与修订

状态：第二轮迭代完成，第三轮检查在跑。本文件记录发现、修订落点与可复现检查。规范以 `docs/rfcs/` 为准。

## 1. 方法与边界

形式化规格在 `proof/proof_rfc/design/architecture/`，通过 `ssot check`。可执行有限状态搜索在 `proof/proof_rfc/design/appendix/reference/`，每个脚本覆盖一条状态转换，输出最短见证轨迹、探索状态数与有界范围内的结论。

结论的性质是：**在有界状态空间内否证或找不到反例。** 没有找到反例不等于不存在反例。外部作业可以永远不结束，已丢失的信息可以永久未知。

故障假设：消息可重复、乱序、丢失；节点可在任意一步崩溃或长时间离线；平台侧结果未知；注入返回不代表已消费；游标与通知可丢失。公平性只在明确写出时成立。

F6 的结构性消除来自你的约定：有积压就不交接。积压清零前交接被拒，于是交接时不存在「未读旧事件」这个类别，旧积压无人可读的轨迹不再可达。代价是处理者永久离线时资源无法易手，只能等保留期给出终态。

## 4. 第三轮发现与修订

| 编号 | 新轨迹 | 修订 |
|---|---|---|

## 6. 复现方式

```sh
ssot check proof/proof_rfc/design
python3 proof/proof_rfc/design/appendix/reference/check_faults.py
```

第一条做类型检查、QuickCheck 与证明义务统计。第二条汇总当前规则的有限状态搜索。两条都通过，只说明在这些边界内没有反例或找到了预期反例。

## 7. 剩余边界

- 有积压不得交接是一条活性取舍。处理者永久离线时，资源只能等保留期终态；协议不提供把积压交给别人的路径。
- `ssot check` 报 49 条证明义务，其中可证 21 条、未定 28 条。未定的集中在隐式操作可满足性与类型局部性，处理记录在 `proof/proof_rfc/SSOT.md`。
- MCP 的外部副作用无法承诺恰好一次。协议只保证调用身份保留与 `unknown` 结局。
- 有限状态搜索只覆盖每个脚本写明的事件数、页数与深度。
