# Onlyne v3 形式化：SSOT 与故障边界

状态：进行中。本文是查找缺陷的工作文档，不是规范。规范仍以 `docs/rfcs/` 为准。

## 1. 这次形式化要回答的问题

目标不是论证 RFC 完美。目标是找出四类风险：

| 风险 | 含义 |
|---|---|
| 消息阻塞 | 一条消息已经产生，但永远没有节点把它推进到下一状态 |
| 队列阻塞 | 一条待处理项卡在队头，后面的项无法推进 |
| 信息丢失 | 某个节点曾经知道的事实，在之后的状态里无法恢复，且没有标记为未知 |
| 节点掉线卡死 | 一个节点离线或重启后，没有规则让它重新取得推进条件 |

## 2. SSOT 用法

每条事实只有一个权威写入点。其他位置保存的是投影或观察值，不各自决定状态。

| 事实 | 权威写入点 | 派生位置 |
|---|---|---|
| 消息是否接纳 | 接收节点（0003 §3、§4） | 发送方出站记录 `admission` |
| 消息存盘条目与 seq | thread 的 owner（0002 §1） | 任何成员的列表视图 |
| 关注分发是否发生 | 接收节点在接纳事务内记录 | agent inbox 视图（0004 §1） |
| 注入是否发生 | 运行时注入游标（0004 §5、0008 §4） | 工具结果与提示 |
| 等待是否解除 | 发送方库等待者（0005 §3） | 工具返回的答复 |
| 资源绑定与 revision | 资源 endpoint（0006 §4） | agent 缓存 |
| 资源操作结果 | 资源 endpoint（0006 §1） | 调用方的 `pending`/`committed` 观察 |
| todo 是否存在 | 运行时（0005 §4、0008 §6） | Onlyne 的本地来源关联 |

SSOT 在这里的具体用法：**当两个位置都能声称同一事实时，只有权威写入点能推进状态。** 派生位置落后是允许的，前提是它明确标记为落后或未知，而不是自行判定。

## 3. 抽象掉的表面实体

建模时不区分这些表面的差异，只保留它们对推进条件的影响：

- thread、IM 会话、计算作业、数据源、MCP server 都抽象为「一个有权威写入点的对象」。
- 具体错误码抽象为三类：可重试、终态拒绝、未知。
- `@all`、`@role`、引用回复、普通通信抽象为「是否产生一个必须被消费的关注项」。
- 域与机器抽象为「可达性」和「委托是否有效」。

## 4. 故障假设

模型允许这些事发生：

- 消息重复到达、乱序到达、永不到达。
- 节点在任意一步之后崩溃或长时间离线。
- 资源 endpoint 接受请求后，平台侧结果未知。
- 运行时注入返回不代表已消费（OMP 的 `sendMessage` 返回 void）。
- 游标和订阅通知可以丢失，且不一定能补齐。

## 5. 不检查什么

- 不检查加密算法、认证强度。
- 不检查性能与容量。
- 不证明系统正确。**有界状态搜索只能否证性质，不能证明性质。**
- 不把「模型没找到反例」写成「不存在反例」。

## 6. 当前产出

- `proof/proof_rfc/design/`：SSoT 形式化规格（`ssot check` 通过，类型检查无错误，QuickCheck 未找到反例；49 条证明义务中 28 条未定，逐条记录在下一节）。
- `proof/proof_rfc/design/appendix/reference/`：可执行有限状态搜索脚本。每个脚本只覆盖一个状态转换，输出最短见证轨迹、探索状态数与有界范围内的结论。
- `proof/proof_rfc/FINDINGS.md`：候选缺陷、分类、RFC 依据与最小修订建议。

实测：`python3 proof/proof_rfc/design/appendix/reference/check_faults.py` 的 8 个模块、27 项检查全部通过。`ssot check proof/proof_rfc/design` 通过类型检查与 QuickCheck。

## 7. 证明义务的处理

`ssot check` 报告 49 条证明义务，其中 21 条可证、28 条未定。未定的义务集中在隐式操作的可满足性与类型局部性，例如 `Accept` 的 satisfiability 和 `Binding` 的 map apply 义务。这些义务不由 QuickCheck 自动闭合；逐条核对时依赖操作 `pre` 已排除越界参数，以及 `post` 的每个分支都有赋值。它们不影响本次缺陷搜索的结论，因为反例来自可执行状态搜索，不依赖未定义务成立。

「没有找到反例」只表示在当前有限边界内没有反例。边界写在每个脚本的输出里。
